# UI品質アップ（ui-quality-boost）

「動けばいい画面」を「プロが作ったように見える画面」にするためのスキルです。やることは3つだけです：**見た目の設計図を先に決める → 正しい部品名で組む → 動きを型どおりに足す**。素材サイトの知識は、その3つを速く・確実にするための引き出しとして使います。

## 付属資料（必要なときに読む）
- `references/motion-recipes.md` … 素のHTML/CSS/JSでそのまま使える動き・見た目のレシピ20種（ボタン、光る文字、カウントアップ、進捗バー、トースト、スクロール登場、スピナー、流れ星、スポットライト、すりガラス、紙吹雪、Anime.jsの連続演出）。Chromiumで動作確認済み。**素材サイトに接続できないときは、これで再現する。** 全部を読まず、冒頭の目次から使う番号だけ読めば十分。
- `references/resource-catalog.md` … 29素材の中身・技術構成・料金・利用条件・借りたい技・コードの取り出し先（GitHub）。特定の素材名が出たとき、利用条件を確かめたいときに読む。
- `references/design-tokens-template.md` … 色・文字・余白・動きの変数のひな形と DESIGN.md のひな形。
- `scripts/check_page.js` … HTMLをブラウザで開き、PC幅・スマホ幅のスクリーンショット、JavaScriptエラー、横はみ出し、「動きを減らす」設定での挙動をまとめて確認する（`node scripts/check_page.js page.html`）。Playwrightがない環境では何もせず終わる。

グラフやダッシュボードを作るときに、グラフ専用のスキル（dataviz など）があれば、グラフの形・配色・目盛りはそちらに従い、このスキルは部品・動き・仕上げを受け持ちます。

## 進め方

### 1. 作るものと技術構成を見極める
技術構成によって使える素材がまったく違うので、最初に判定します。

| 構成 | 例 | 使う素材 |
|---|---|---|
| 素のHTML（ビルドなし） | 1ファイルのHTML、Claudeのアーティファクト、既存の静的サイト | レシピ集、#14 Kinetics、#24 CSS Text Effects、#19 Uiverse、#26 Gradient Buttons、#29 Anime.js、canvas-confetti、#28 3dicons、#27 Kitbitz |
| React＋Tailwind | Next.js／Viteのプロジェクト | 土台に #15 shadcn/ui、演出に #17 Magic UI・#18 Motion Primitives・#16 Aceternity UI（条件注意）、部品探しに #13 21st.dev、#22 MicroKit UI、#23 Liquid Glass |
| その他（Vue、スライド、画像など） | | 見た目の考え方（手順2〜4）とレシピ集の考え方を移植して使う |

React用の素材を素のHTMLで使いたいときは、コードを持ち込まずに「動き方」を読み取って素のCSS/JSで書き直します（レシピ集にほぼ同等のものがあります）。

### 2. 見た目の設計図（トークン）を先に決める
色・文字サイズ・余白・角丸・影・動きの時間を CSS変数にまとめてから部品を作ります（`design-tokens-template.md`）。
- 強調色は基本1色。主ボタン・リンク・選択中の表示にだけ使うと、どこを押せばいいかが一目で分かる。
- 余白は4の倍数、文字サイズは4〜5段階に絞る。数値がそろうだけで「整って見える」。
- 既存プロジェクトでは、既存の変数・DESIGN.md に従う。新しい色を直接書き足さない。
- 雰囲気の参考が欲しいときは #4 Refero Styles・#11 DESIGNmd のスタイルや、#2・#6〜#10 のギャラリーの考え方を借りる（丸写しはしない）。

### 3. 正しい部品名で組む
#5 Component Gallery の呼び方（Button の主・副、Toast、Modal、Tabs、Progress bar／Meter、Skeleton、Tooltip、Accordion など）で画面を分解すると、状態（ホバー・押下・無効・読み込み中・空・エラー）の抜けがなくなります。とくに「読み込み中」「0件」「エラー」の表示を用意するだけで完成度が大きく上がります。

### 4. 動きを型どおりに足す
動きは次の4種類に分けて考え、上から順に入れます。

1. **反応**（全部に）：ホバー・押下・フォーカス。140ms前後。押し心地は `--ease-spring`（レシピ1・2）。
2. **切り替え**：開く・閉じる・タブ・進捗。240ms前後、`--ease-out`（レシピ10・12）。
3. **登場**：一覧やカードを時間差で出す。400〜700ms、1項目ごとに40〜80msずらす（レシピ8・13）。
4. **見せ場**：数字のカウントアップ、光る枠、流れ星、紙吹雪など。**1画面に1〜2個まで**（レシピ3〜6・9・16・19）。多すぎると安っぽく、読みにくくなる。

動かすのは `transform` と `opacity` を基本にします（幅や位置を動かすと、ページ全体の再計算でカクつきやすいため）。

### 5. 素材を使う・探すときの手順
1. `resource-catalog.md` の早見表から目的に合う素材を選ぶ（下の「目的別の早見表」）。
2. 素材サイトを開いてみる。作業環境によっては通信制限で開けないことが多い。
3. 開けなければ GitHub（github.com／raw.githubusercontent.com）や npm（registry.npmjs.org）の「取り出し先」を試す。こちらは開けることが多い。
4. どちらも無理なら、レシピ集で同等の表現を自作する。「素材サイトが開けないので作れません」とは言わない。
5. 外部ライブラリを読み込むときは、版を固定して cdn.jsdelivr.net か cdnjs.cloudflare.com から読み込む（アーティファクトではこの2つ以外から読み込めない）。使わなくて済むならCSSだけで作る。

### 6. 利用条件を守る
- **MIT**（自由に使える代表的なライセンス。著作権表示のコメントは残す）：Kinetics、CSS Text Effects（どちらもサイト上の表記のみ）、Uiverse、Magic UI（無料部品）、Motion Primitives（無料部品）、shadcn/ui、MicroKit、Liquid Glass、mapcn、UIAble（GitHub版）、Anime.js、21st.dev（大半、部品ごとに確認）。
- **CC0**（著作権放棄。クレジット不要）：3dicons、Kitbitz。
- **独自ライセンス**：Aceternity UI（完成品への組み込みは可。コードの再配布・部品集としての配布・自由なライセンスでの公開は不可）、Scrolltide（有料）。
- **条件の表示が見つからない**：Circle Loaders → 自作する。
- **スクショ集**（Minimal、AppShot、Navbar、Footer、CTA、404s）：他社のデザインなので参考のみ。
- 迷ったら「コードは写さず、技法を参考に一から書く」。レシピ集はすべてこの方針で書かれている。

### 7. 仕上げチェック（完了と言う前に）
- [ ] 色・余白・文字サイズが変数から来ている（直書きの色が散らばっていない）
- [ ] すべての押せる部品に `:hover` と `:active`（スマホ用）と `:focus-visible`（キーボード用）がある。押せる大きさは44px以上
- [ ] `prefers-reduced-motion` で動きが止まる（JSの演出も。レシピ0・20）
- [ ] 見せ場の演出は1画面に1〜2個
- [ ] 文字と背景の明暗差が十分ある（薄いグレーの文字を使いすぎない）
- [ ] 読み込み中・0件・エラーの表示がある（該当する場合）
- [ ] 既存プロジェクトでは、既存のクラス名・変数名・アニメーション名を変えていない。新しいものには接頭辞を付けた
- [ ] 画像は表示サイズに縮めてある。外部ファイルは版を固定している
- [ ] スクロールで登場する演出を使ったら、印刷や全体スクリーンショットで中身が消えない（レシピ13）
- [ ] 見た目を確かめた。確認は作業の大きさに合わせる：
  - 素のHTML → `scripts/check_page.js` で PC幅・スマホ幅の画像を見て、エラー・はみ出し・「動きを減らす」設定を確認する（Playwrightがなければ、コードを読み直して机上で確認し、その旨を伝える）
  - React などの部品だけを頼まれたとき → 構文・型の確認と、クラス名・状態の読み直しで十分。確認のためだけにプロジェクト一式を新しく組み立てない（時間がかかりすぎる。依頼者が求めたときだけ行う）

## 依頼者への伝え方
完成物を渡すときは、どの技法・素材を使ったかを1〜2行で添えます（例：「ボタンは押し心地のある動き、数字はカウントアップ、見せ場はヘッダーの光る枠の1点に絞りました」）。外部素材を使った場合は、その利用条件（MIT／CC0／要確認）も一言添えます。
