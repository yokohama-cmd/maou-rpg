## 5. 使うときの共通の注意

素材をゲームに取り入れるときは、AIへの依頼に次の文をそのまま付け足してください。

```
maou.html は React・Tailwind・ビルド作業を使わない、HTMLファイル1つの構成です。
次の素材を、素のHTML／CSS／JavaScriptに書き直して組み込んでください。
- 既存のコードや埋め込み画像は消したり書き直したりせず、必要な箇所だけを追加・変更する
  （ファイルの大半は埋め込み画像なので、ファイル全体を出し直さないこと）
- 色は既存のCSS変数を使い、新しい色を直接書かない
  （背景：--bg, --bg2, --panel, --panel-line／文字：--ink, --ink-dim／
   強調：--blood, --blood-bright, --ember, --gold／ゲージ：--hp, --mp, --xp, --green）
- 書体は既存（Shippori Mincho B1／Cinzel）を維持し、素材側の書体指定は消す
- 新しく追加するクラス名・アニメーション名・CSS変数名にだけ「mo-」を付ける（既存の名前は一切変えない）。
  既存の .btn / .cta / .ghost / .good / .back、pop / shake / fade、--ink などと重ならないようにする
- 今ある演出（ダメージ数字、揺れ、LEVEL UP表示など）と二重にならないよう、既存の演出を確認してから足す
- スマホにはマウスを乗せる操作がないので、:hover の演出は :active（押したとき）にも付ける
- 素材に入っている作者名・ライセンスのコメントは消さずに残す
- 画像は表示サイズ（64〜128px程度）に縮小してから埋め込む
素材：（ここにURLまたはコードを貼る）
```

### 利用条件（ライセンス）の注意
このリポジトリはGitHub上で**公開設定**になっており、maou.html の中身は誰でも見られます（現時点ではライセンスのファイルは置かれていません）。
- MIT の素材（#14、#17、#18、#19、#22、#23、#24、#29 など）：自由に使えます。作者名・著作権表示のコメントは残してください。
- CC0 の素材（#27、#28）：クレジット表記も不要で自由に使えます。
- 独自ライセンスの素材（#16 Aceternity UI）：ゲームに組み込んで公開すること自体は可。ただし移植したコードを部品集として配ったり、このリポジトリにMITなどの自由なライセンスを付けたりすると、規約に触れるおそれがあります。
- 利用条件の表示が見つからない素材（#25）：作者に確認するまでは見た目の参考にとどめます。

迷ったら「コードはコピーせず、動きを参考に一から書いて」とAIに頼むのが安全です。

### ゲーム用「見た目ルール書（DESIGN.md）」の作り方
#4・#11 で紹介されている形式を真似て、AIに次のように頼むと作れます。作ったファイルをリポジトリに置き、以後の修正依頼のたびに「DESIGN.md に従って」と添えると、見た目がぶれにくくなります。

```
maou.html にある12個の <style> ブロックをすべて読み（後ろのブロックが前の指定を上書きしているので、
最終的に効いている値を使う）、今の見た目のルールを新しいファイル DESIGN.md にまとめてください。
色（CSS変数）、書体の使い分け、文字サイズ、余白、角丸、ボタン（.btn と、その種類 .cta / .ghost / .good / .back）、
ゲージ（HP/MP/XP）、ポップアップ（#modal / .sheet）、アニメーション（@keyframes）、
画面幅（最大560px・スマホ縦画面）を含めてください。新しいルールは作らず、今の実装から読み取れることだけを書いてください。
maou.html 自体は変更しないでください。
```

## 6. 調べ方と限界

- 各サイトは作業環境の通信制限で直接開けませんでした。代わりに、検索エンジンの結果、GitHubのソースコード・説明書、npmの配布データで確認しています。

- 料金はセール価格を含み、変わりやすい情報です。有料サービスを使う場合は、必ず購入前に公式サイトで確認してください。
- 利用条件に注意が必要な素材（#16 独自ライセンス、#25 表示が見つからない、#26 ボタンのCSSは明示なし）は、ゲームに入れる前に各サイトの表記を自分の目で確認してください。ライセンスについての記述は規約の文面からの読み取りで、法的な確認ではありません。
- ゲーム側の記述（ボタン名・画面名・色の設定・今ある演出）は、maou.html の実物と照らし合わせて確認しました。文書の完成後に別の担当が点検し、見つかった食い違い（ボタン名の誤り、すでにある演出を新機能のように書いていた箇所など）を直しています。
